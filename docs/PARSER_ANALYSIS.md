# Анализ источника данных: расписание и замены kasict.ru

Документ основан **исключительно на реальных данных**, скачанных с сайта колледжа
(файлы лежат в `backend/tests/fixtures/`, чтобы тесты не зависели от доступности сайта):

- страница расписания: `https://kasict.ru/students/schedule/` (фикстура `schedule_page.html`)
- основное расписание: `Raspisanie_2025-2026.htm` (фикстура `raspisanie.htm`, 615 КБ)
- замены: `zamena1.htm` (фикстура `zamena1.htm`, 71 КБ)

Все три файла — Excel-выгрузки в HTML (charset **windows-1251**, генератор
«Microsoft Excel 15», пространства имён `urn:schemas-microsoft-com:office:excel`).
Таблицы активно используют `colspan`/`rowspan`, поэтому парсинг построен на
**развертке таблицы в виртуальную сетку ячеек**, а не на CSS-селекторах.

---

## 1. Страница-указатель `/students/schedule/`

Содержит ссылки на файлы (имена файлов **могут меняться** от семестра к семестру):

| Назначение | Текущее имя файла | Как ищем |
|---|---|---|
| Основное расписание | `files/Raspisanie_2025-2026.htm` | ссылка, в href которой есть `raspisan*` и нет `zaoch` |
| Замены (очное) | `files/zamena1.htm` | ссылка с `zamena*` и без `zaoch` |
| Замены (заочное) | `files/zaoch_zamena.htm` | ссылка с `zaoch` (не используется, но фиксируется) |

На этой же странице опубликована **сетка звонков** (см. §6) — она захардкожена
в коде как константа, т.к. меняется крайне редко.

Если страницу-указатель открыть не удалось, используются последние известные
ссылки из кэша; при полном отсутствии кэша — запасные URL текущих файлов.

## 2. Основное расписание (`Raspisanie_*.htm`)

Одна HTML-таблица ~65 строк × 149 колонок (с учетом colspan).

### 2.1 Структура

```
строка 0:  «1 курс 2025-2026 уч.г.» | «2 курс …» | «3 курс …»   (colspan-заголовки)
строка 2:  «ДНИ» | [Группа A][№][пустая] | [Группа B][№][пустая] | ...
строки:    блоки дней (Пн..Пт), по 6 пар, на каждую пару ДВЕ строки:
             строка пары:     буква дня | № пары | предмет | кабинет | ...
             строка учителя:  буква дня |  —      | учитель | кабинет | ...
```

- **Каждая группа занимает 3 колонки**: `[название группы] [№ группы] [пустая]`.
  Например `СЗС 24-4 | 27 | (пусто)`. Названия: `А 25-1`, `СЗС 24-4`,
  `ТЭСМО 25-1П`, `М 24-1П` и т.п. В файле 2025–2026 уч. года — **48 групп**.
- **Дни идут вертикально, 5 блоков** (Пн–Пт). Название дня записано
  **вертикально по одной букве в первой колонке**: `П|О|Н|Е|Д|Е|Л|Ь|Н|И|К`,
  `В|Т|О|Р|Н|И|К`, `С|Р|Е|Д|А`, `Ч|Е|Т|В|Е|Р|Г`, `П|Я|Т|Н|И|Ц|А`.
- Границы дней определяются **сбросом номера пары на `1`** (в колонке 1).
  Дополнительная проверка — собранное из букв слово должно совпасть с днем.
- **Номер пары** — число `1..6` в колонке 1 строки пары.
- **Предмет** — ячейка группы в строке пары; **кабинет** — соседняя ячейка
  справа (или через одну); **учитель** — ячейка группы в СЛЕДУЮЩЕЙ строке.
- Между блоками дней бывают пустые строки-разделители.

### 2.2 Числитель/знаменатель (нечётная/чётная неделя)

В ячейках встречается формат `X/Y`:

| Пример | Значение |
|---|---|
| `общ./-` | нечётная неделя — «общ.» (обществознание), чётная — пары нет |
| `-/физ.` | нечётная — пары нет, чётная — физика |
| `геогр./инф.` | разные предметы по неделям |
| `мат.` | без слэша — одинакова на обеих неделях |

То же касается учителя (`Кухаренко/-`, `Рудых/Карпова`) и кабинета.
**`-` = занятия нет.** Слэш делит ровно на 2 части; части могут быть пустыми.

### 2.3 Особые значения

| Значение | Смысл |
|---|---|
| `кл.час "Разг. о важн."` | классный час (обычный предмет) |
| `физ-ра`, `004`/`002` и т.п. | физкультура, кабинеты «002» (зал) |
| `до` в кабинете | дистанционное обучение (встречается в заменах) |
| пустая ячейка | пары нет |

### 2.4 Чётность недели (правило)

В основном расписании нет дат — только дни. Чётность конкретной даты
вычисляется так:

- **Якорь**: неделя (понедельник–воскресенье), в которую попадает **1 сентября**
  учебного года, считается **нечётной (числитель)**.
- Далее чётность чередуется по неделям.
- Проверено на реальном файле замен: 26.06.26 — «нечетная пятница»,
  29.06.26 — «четный понедельник» — обе даты сходятся с якорем 01.09.2025
  (понедельник). При расхождении сервис **калибруется** по заголовку замены
  (сдвиг чётности), а конфликт двух блоков логируется как WARNING.

## 3. Страница замен (`zamena1.htm`)

Файл состоит из **нескольких блоков**, каждый начинается заголовком-ячейкой
(colspan на всю ширину):

```
Изменения в расписании на 26.06.26 (нечетная пятница)
```

Из заголовка достоверно извлекаются: **дата**, **чётность недели**
(`нечетный/четный`), **день недели** (используется для самопроверки).

### 3.1 Колонки таблицы

```
№ группы | Название группы | Пары | Предмет | Фамилия преподав. | кабинет
```

У одной группы может быть **несколько строк** (по одной на изменение).

### 3.2 Все реально встречающиеся форматы ячейки «Пары»

| Пример из файла | Семантика | Разбор |
|---|---|---|
| `1` | одна пара | `[1]` |
| `1,2` / `2,3` / `5,6` | несколько пар | список номеров |
| `с 4 пары` | **с N-й пары до конца дня** | `[4,5,6]` |
| пустая ячейка | **весь день** | `[]` (весь день) |

### 3.3 Все реально встречающиеся типы строк замен

| Пары | Предмет | Пример | Тип замены |
|---|---|---|---|
| `1,2` | `нет пары` | `А 23-1 │ 1,2 │ нет пары` | **отмена** пар |
| `3` | `огп` + учитель + кабинет | `А 23-1 │ 3 │ огп │ Булычева │ 304` | замена/добавление одной пары |
| `2,3` | `кзс` | `А 23-2 │ 2,3 │ кзс │ Матькова │ 311` | замена нескольких пар |
| `с 4 пары` | `УП 01.01` | `Д 23-2 │ с 4 пары │ УП 01.01 │ Рудых │ 303` | с 4-й и до конца дня практика |
| пусто | `сессия` | `А 25-1 │ · │ сессия` | **весь день** — сессия |
| пусто | `уп.02.01` | (в файлах прошлых лет) | весь день — учебная практика |

Правила, выведенные из сопоставления с основным расписанием:

- **«нет пары»** — пары отменяются; исходные пары сохраняются для отображения
  «Было → Стало».
- Строка с конкретными номерами пар **полностью замещает** эти пары:
  и предмет, и преподавателя, и кабинет — независимо от того, что было
  в основном расписании (замена дисциплины, преподавателя или кабинета —
  всё это одна и та же строка файла; тип определяется сравнением с базой).
- Если в основном расписании на этой паре **пусто**, а в замене есть предмет —
  это **добавленная пара**.
- Строка «весь день» (`сессия`, `УП 01.01`) замещает **все 6 слотов**;
  в интерфейсе отображается как заметка на весь день + пары с этой пометкой.

### 3.4 Шум и нестандартные секции

- После блока замен в файле встречается секция с заголовком **«Кабинеты»**
  и пустыми строками — игнорируется (строки без № группы и названия).
- В файлах прошлых лет в конце бывали строки **без номера группы и названия** —
  служебные записи для преподавателей. Правило: строка валидна только если
  указано **название группы**; иначе она пропускается с WARNING в лог.
- Возможна 7-я колонка «корпус» — читается опционально и не используется.

## 4. Сопоставление групп

- В заменах группа записывается так же, как в основном расписании
  (`СЗС 24-4`, `А 23-1`). Для надёжного сравнения названия
  **нормализуются**: удаление пробелов/дефисов/точек, верхний регистр
  (`СЗС24-4`). Совпадение ищется только по нормализованной форме.
- Если группа из замены не найдена в основном расписании — замена
  **не применяется** (данные не выдумываются), в ответ API и лог попадает
  предупреждение: `⚠ Замена для неизвестной группы «X» не применена`.

## 5. Неоднозначные случаи и как они обрабатываются

| Случай | Решение |
|---|---|
| Не удалось собрать слово дня из букв | день определяется позиционно (1-й блок = Пн и т.д.) + WARNING в лог; при расхождении с буквами — данные всё равно позиционные, расхождение логируется |
| Номер пары вне 1..6 | замена игнорируется, WARNING |
| Блок замен с нечитаемой датой | блок пропускается целиком, WARNING |
| Конфликт чётности двух блоков (нечет/чет на одну дату) | берётся последний, WARNING |
| Замена поверх замены (две строки на одну пару) | применяется по порядку файла: последняя строка выигрывает |
| Группа из замены неизвестна | не применяется, WARNING |
| Кабинет `до` | сохраняется как есть; фронтенд показывает бейдж «дистанционно» |
| Сайт недоступен | отдаётся последний успешно распарсенный результат (кэш на диске) + пометка `stale` в `/api/health` |

## 6. Сетка звонков (со страницы расписания)

Пара = два урока по 45 минут с 5-минутным перерывом внутри пары:

| Пара | Начало | Конец |
|---|---|---|
| 1 | 08:00 | 09:35 |
| 2 | 09:45 | 11:20 |
| 3 | 11:45 | 13:20 |
| 4 | 13:45 | 15:20 |
| 5 | 15:30 | 17:05 |
| 6 | 17:15 | 18:50 |

## 7. Выводы для архитектуры

1. Парсеры выдают нормализованные структуры (`Lesson`, `Replacement`) и
   **никак** не применяют бизнес-логику.
2. Replacement Engine получает базовый день (с учётом чётности недели) и список
   замен на дату, сравнивает поля и классифицирует каждое изменение:
   `replaced / teacher_changed / room_changed / cancelled / added`.
3. Всё, что не удалось разобрать однозначно, не теряется молча:
   собирается в `warnings` (лог + ответ API).
